## 코드 표현

- 경로는 `import os`와 `os.path.join`으로 작성함. `Path`의 `/` 연산이나 `next(... for ...)`로 경로를 압축해서 찾지 않음.
- `DATA_DIR`, `FIG_DIR`, `TEMP_CSV`, `EVENT_CSV`처럼 폴더와 파일을 명확한 변수로 둠. CSV는 노트북 셀에 `pd.read_csv`를 직접 보여줌.
- CSV 인코딩은 팀 양식의 `ENC = "utf-8-sig"`를 사용함. 기존 날짜 변환, 자료형, 행 순서, 결측 처리 의미를 유지함.
- 현재 폴더는 `notebooks/namelesspark`이므로 원문 양식의 `../data`를 그대로 복사하면 안 됨. 저장소 루트, `notebooks`, `notebooks/namelesspark`에서 같은 파일을 읽도록 간단한 if문으로 경로를 정함.
- 긴 generator, 중첩 comprehension, 별표로 목록을 펼치는 문법은 명시적인 변수, for문, 목록 더하기로 풀어 씀. 파일명을 조합할 때는 간단한 문자열 더하기를 우선 사용함.
- 설명, 주석, 그래프 제목에는 가운데점 대신 쉼표나 자연스러운 문장을 사용함. 실제 컬럼명, 원본 값, 저장된 라벨 근거, 판정 규칙은 가독성 수정만으로 바꾸지 않음.
- 사용자는 같은 날 추가로 외부에서 만든 함수 호출도 없애 달라고 요청했음. `from namelesspark_pipeline import ...` 같은 개인 모듈 import를 사용하지 않음. CSV 읽기, LOT 연결, 정비 조인, 파생 계산, 라벨 판정, 저장까지 계산 과정이 노트북 셀에 직접 보여야 함.
- 계산은 `pd.read_csv`, `merge`, `groupby`, `loc`, `shift`, `rolling`과 명시적인 for문을 우선 사용함. 계산 단계를 짧은 설명과 여러 셀로 나눔. 긴 함수 정의를 노트북으로 복사한 뒤 호출하거나 `exec`, `runpy`로 외부 코드를 실행하는 방식으로 우회하지 않음.
- 코드 셀 안에서도 집계, 조인, 조건 검사, 반복문, 후처리 등 처리 단계 사이에 빈 줄 하나를 둠. 반복문 안의 독립 단계도 띄우되 import, 경로 설정, 관련 변수처럼 한 묶음인 줄은 붙여둠. 공백을 정리할 때 계산식과 판정 조건은 바꾸지 않음.
- 2026-10-16 추가 요청: 검사만 하는 `if ... raise`, `assert`, `pd.testing.assert_*`는 노트북에 넣지 않음. 검사에만 쓰던 변수와 반복문도 정리함. 실제 제외, 후보 선택, 라벨 판정에 필요한 조건문과 분석 결과를 보여주는 표는 유지함.
- 필요한 표준 라이브러리와 pandas, NumPy import는 사용해도 됨. 기존 주기 분석의 FFT 등은 결과를 보존하기 위해 해당 NumPy 계산을 셀에 직접 보임. 파일 무결성 해시는 `hashlib`로 계산 과정을 직접 씀.
- 원문에 있는 WELD_CSV는 용접 파일 경로임. 경로가 양식에 있다는 이유로 현재 소둔로 분석에 새 데이터를 조인하지 않음.
- 그래프가 있는 노트북은 팀 양식의 한글 폰트 후보와 `axes.unicode_minus=False` 설정을 적용함. 실제 그림 저장 위치는 `figures/namelesspark` 아래 기존 노트북별 폴더임.

```python
import os
import pandas as pd

DATA_DIR = os.path.join(ROOT, "data")
TEMP_CSV = os.path.join(DATA_DIR, "T-CR1-CAL01_온도.csv")
ENC = "utf-8-sig"

temp = pd.read_csv(TEMP_CSV, encoding=ENC)
temp["MEAS_DT"] = pd.to_datetime(temp["MEAS_DT"], errors="raise")
```

## GitHub 양식

- 커밋 첫 줄은 `타입: 변경 요약`. 날짜, 시간, 끝의 마침표는 쓰지 않음.
- 본문은 `추가`, `변경`, `삭제`, `이유`, `Refs #번호` 양식을 사용하고 해당 없는 항목은 지움.
- PR은 원문의 `변경 내용과 이유`, 변경 전후 표, `연결한 작업`, `확인한 결과`, `리뷰어에게`, 검토 항목 순서를 따름. 실행한 검증만 적음.
- 완료한 이슈만 `Closes #번호`로 연결함. 진행 중인 모델링이나 미확정 도메인 검토는 `Refs #번호`로 남김.
- 파일을 지정해서 stage함. 원본과 가공 CSV는 Git에 올리지 않고 노트북 출력은 비움.
- `refactor`, `test` 타입은 확인 당시 Notion에 팀 합의 후 반영할 제안으로 표시되어 있었음. 합의된 것으로 단정하지 않음.
