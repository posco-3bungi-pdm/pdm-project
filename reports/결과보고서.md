## 1. 문제 정의

### 1.1 대상 설비와 현장 문제

- 대상은 냉연 라인 CR1의 연속소둔로 CAL01 한 대다. 강판이 세정, 건조, 가열, 균열, 과시효, 냉각 순서로 지나가며 구역마다 온도(TC)와 히터 출력(OP)을 기록한다. 가열 구역 Z4에는 분위기 값 CP-Z4가 더 있다. 센서는 22개다.
- 조업 조건이 바뀌면 온도와 출력의 평소 값도 같이 바뀐다. 온도가 유지돼도 출력이 계속 높아지는 경우가 있다. 반대로 강종 변경으로 값이 달라진 구간을 이상으로 잘못 잡을 수 있다. 비슷한 조업 조건에서 온도와 출력의 변화가 큰 구간을 찾고, 함께 확인할 정비 기록을 붙였다.

### 1.2 정상, 이상의 정의와 성공 기준

| 구분 | 팀 문제정의서의 정의 | 이 보고서의 구현 |
| --- | --- | --- |
| 정상 | 비슷한 조건과 견주어 TC, OP가 평소 범위 안이고 크게 흔들리지 않음. 강종을 바꿔 값이 달라져도 시간이 지나 안정되면 정상 | 통계 후보가 아니거나, 팀이 검토 후 후보에서 해제한 구간. 라벨 0 전체를 실제 정상으로 확인한 것은 아님 |
| 이상 후보 | 평소보다 많이 벗어나거나, 흔들림이 커지거나, 온도는 그대로인데 출력만 오르는 구간 | 센서 하나라도 3σ를 넘은 1분(STAT_LABEL)을 팀이 그래프로 보고 단독 튐 1, 공통 움직임 0으로 적음(DOMAIN_LABEL). 규칙 2개로 제어 반응과 잡음을 뺌 |
| 점검 경보 | 오래 가거나 반복되고 조업 조건 변경으로 설명이 안 되는 후보 | Z-score 경보 묶음 중 후보 단위 RandomForest 점수 0.5 이상 |
| 아닌 것 | 실제 고장이나 남은 수명. 이상 점수가 높아도 바로 고장으로 보지 않음 | 실제 고장 발생 시각은 제공되지 않았다. 분석 라벨은 점검 후보를 뜻한다 |

- 성공 기준(문제정의서): LOT을 섞지 않고 같은 코드로 같은 결과가 나올 것, 조건별 기준이 잘못된 경보를 줄일 것, 기준 모델과 머신러닝을 같은 LOT으로 비교할 것, 이상 후보 2개 이상을 그래프와 기록으로 확인할 것, 점검 목록을 낼 것. 확인 결과는 5.1절, 5.2절, 6장, 7장에 있다. 실제 고장 예측 성능으로 해석하지 않는다.
- 계획과 달라진 것: XGBoost와 Optuna는 쓰지 않았다 (5.6절). 1분 단위 F1에 더해 경보 묶음(후보) 단위 평가를 더했다 (5.5절).
- 숫자는 원본 CSV와 저장된 결과 파일에서 확인했다. 4장은 정수진이 작성한 시계열 분석 보고서(54쪽, 2026-10-22)의 요약이다. 원본 PDF는 [보고서 목록](README.md)에서 볼 수 있다.

## 3. 전처리

### 3.1 처리 절차와 전후 비교

표 3-1. 처리 단계 (코드: `notebooks/namelesspark/06_cal01_base_v1.ipynb` - `13_cal01_base_v7.ipynb`)

| 단계 | 처리 | 근거 |
| --- | --- | --- |
| 강종 붙이기 | LOT 첫 기록과 시각이 같은 강종 변경 기록의 바뀐 뒤 강종 | 조업 이벤트 파일 |
| 제외 구간 | 240058 06-09 08:00 이후 노 내림(63분), 240061 06-15 02:30 이전 승온(86분), 240114 11-04 20:00 이후 정기수리 전 하강(60분), 240117 11-13 09:00 이전 정기수리 후 승온(112분). 행은 지우지 않고 EXCLUDED 표시 | 정기수리 캘린더와 그래프 확인 |
| 통계 후보 | 같은 LOT 안에서 제외 행을 뺀 평균과 표준편차(ddof=0)로 센서별 Z. \|Z\| > 3인 원래 관측 행이 하나라도 있으면 그 분의 구역 STAT_LABEL = 1 | 통계 후보 선정 기준으로 3σ를 사용. 품질 규격이나 고장 기준을 뜻하지 않음 |
| 1분 묶기 | 센서마다 평균, 최소, 최대, 표준편차와 원래 관측 행 수 | 초 단위의 짧은 변화을 줄이고 입력 단위를 맞춤 |
| 팀 판단 반영 | 검토 표 `data/labels/domain_decisions.csv`의 LOT, 센서, 시작, 끝, 0 또는 1을 해당 분의 DOMAIN_LABEL로 씀 | 공통 움직임 해제(C, J, E, A), 팀 판단(T), 전 구역 검토(S), 모델 후보 검토(M) |
| 규칙 해제 | 출력만 3σ를 넘은 행, 온도가 LOT 평균에서 0.5℃ 미만 벗어난 행은 0 | 팀 판단 T21, T25, T27, T30과 같은 기준 (5.2절) |

- 처리 전후: 초 단위 345,390행을 1분 5,938행으로 묶었고, 제외 구간 321분을 뺀 5,617분을 사용했다. 21개 센서에 분별 최소, 최대, 표준편차를 더했다. 구역별 라벨 1의 합은 통계 후보 2,922개에서 v7 435개로 줄었다. Z4는 527개에서 249개로 줄었다. 검토 표 395행 중 0은 346행, 1은 22행, 빈칸은 27행이다. 이 중 적용 버전인 v2, v3, v6, v7의 361행만 라벨에 반영했다. 제안 또는 보류 버전의 34행은 반영하지 않았다.
- 1분 모델의 이동 통계와 Z-score는 현재 분을 뺀 과거 값으로 계산한다. 스케일러는 사용하지 않으며 정비 이력을 입력에 넣지 않는다. 반면 `STAT_LABEL`은 LOT 전체 통계를 사용하므로 사후 라벨이다. 2단계 후보 모델에는 후보 뒤 10분의 온도 반응도 들어가므로, 후보가 생긴 즉시 내는 실시간 경보로 설명하지 않는다.

## 4. 시계열 분석

### 4.1 전체 시계열의 특성

- 시계열 분석은 정수진의 시계열 분석 보고서에서 다섯 경로(LOT 추세, 이전 30분 기준 시간순 Z, CP 원본 펄스 0.05 기준, IQR, 같은 강종 수준 대조)로 했고 한 경로만으로 판정하지 않았다. 여기서는 모델링과 이어지는 결과만 요약한다.
- 가열 구역 온도는 LOT 안에서 비교적 일정하고, 출력이 온도 변화에 반응하는 구간이 반복됐다. `TC-Z3`부터 `TC-Z6`의 표준편차는 여러 LOT에서 0.3-0.5℃ 수준이었다. 강종 변경 뒤 여러 구역이 함께 움직인 216건은 공통 움직임으로 검토해 후보에서 해제했다. 온도와 출력의 방향이 반대라는 사실만으로 정상이라고 확정하지는 않았다.
- 계획 수리 앞뒤에 온도가 오르거나 내려가는 구간이 있다. 240058에서는 정지 전 약 90분 동안 CP가 약 0.35 하강했다. 240114의 하강 구간에는 같은 CP 사건이 없었다. 운전 전환 구간은 모델 학습에서 제외했다.
- 기본 검토선 \|Z\| ≥ 3은 14 LOT에서 1분 창 356개, 연속 구간 155개를 표시했고, \|Z\| ≥ 4에서는 12 LOT 93개 창 52개 구간이다. CP 0.05 기준의 원본 펄스 사건은 전환 후보를 뺀 6 LOT 14건이다. 연간 14 LOT 관측 약 99시간 동안 CAL01 작업 지시(WO) 44건 중 실제 작업이 관측과 겹친 것은 240117의 TBM, CBM 2건뿐이다.

### 5.1 분석 단위와 데이터 분할

### 5.5 2단계 설계: Z-score가 후보를 찾고 RandomForest가 팀 판단을 배움

- 왜 두 단계인가: 1분 단위 분석 라벨은 1-2분짜리가 많다 (v7 Z4 시험 집합의 라벨 1 묶음 50개 중 1분 15개, 2분 12개). 분 라벨은 LOT 전체 통계를 사용한다. 과거 값만 보는 모델과 기준이 달라 분 경계의 짧은 변화를 맞히기 어렵다. 현장에서는 어느 분이 이상인지보다 이 경보 묶음을 점검할 가치가 있는지를 알아야 한다.
- 설계 (`notebooks/namelesspark/14_candidate_rf.ipynb`): 1단계 Z-score(지난 값 3σ)가 구역마다 3σ를 넘은 분을 찾고 이어진 분을 하나의 경보 묶음(후보)으로 만든다 (14 LOT, 9구역에서 532개). 2단계 RandomForest가 후보 하나의 특징을 보고 팀이 1이라 할지 0이라 할지 배운다 (팀 판단이 있는 후보 214개, 1이 12개, 0이 202개).
- 후보 특징: 온도, 출력, CP의 지난 값 \|Z\| 최대와 벗어난 폭, 출력만 넘었나, CP만 넘었나, 앞뒤 5분 안에 경보가 있던 다른 구역 수, 온도와 출력이 같은 방향으로 움직인 비율, 10분 뒤 온도 \|Z\|, 길이, LOT 시작 후 지난 분(`ELAPSED`), 구역 원핫, 강종 계열 원핫. 모델은 트리 300개, 깊이 제한 없음, 잎 최소 2개, class_weight balanced, random_state 42, 확률 0.5 기준. 평가는 LOT 하나 빼고 학습(14회), 시간순, 앞 7 → 뒤 7 LOT 세 가지다.

### 5.6 시도했으나 채택하지 않은 것

| 시도 | 결과 (v7 Z4 RF F1, 기본 0.585) | 채택 안 한 이유 |
| --- | --- | --- |

- XGBoost와 Optuna를 안 쓴 이유: 과정 규칙이 머신러닝 모델을 최대 3종으로 제한한다. 양성이 165분뿐이고 시간순 분할에서는 탐색으로 고른 설정이 뒤 LOT에서 더 나빴다. 이후에는 라벨 기준과 평가 단위를 검토했다. 버전마다 정답이 달라 점수 상승만으로 모델 개선을 판단하지 않았다.

### 6.5 종합

- Z4 1분 모델은 Z-score 0.598, RF 0.585로 차이가 작고 LOT 전체 통계로 만든 라벨과 1-2분의 짧은 변화가 평가에 영향을 준다. 2단계 후보 RF는 팀 1의 8/12를 잡고 팀 0의 98%를 거르며, 앞 7 LOT으로 배워 뒤 7 LOT을 볼 때 7/8(F1 0.875)이다.
- 결과는 1분 F1 대신 경보 묶음을 얼마나 잘 거르는지로 보고한다. 기준 모델 대비 나아진 점은 오탐 묶음을 줄인 것이다. 실험 조건과 결과는 [실험 기록](../docs/03-experiment-log.md)에 정리했다. 관련 변경은 PR #123, #127, #130이다.

### 7.2 활용 시나리오와 임곗값 근거

- 활용 제안: LOT이 끝난 뒤 1분 데이터와 Z-score 경보 묶음을 만든다. 후보 RF 점수 순으로 정렬하고, 담당자가 그래프와 조업 기록을 보고 1, 0, 보류를 남긴다. 검토 결과는 다음 학습 자료에 반영할 수 있다. 관제 사이트는 저장된 구역별 모델을 읽어 3D 화면에 센서와 후보를 표시한다. 사이트 판단을 검토 표에 자동 반영하는 전체 연결이 구현됐다는 뜻은 아니다.
- 점검 항목: CP 단독 튐이면 가스 분석계 지시값과 교정 기록, O링 기밀을 먼저 본다. 온도 하강형이면 해당 구역 히터와 출력 제한을 본다. LOT 시작 60분 안이면 공통 움직임인지 먼저 확인한다.
