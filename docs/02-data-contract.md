## 1. 독립 표본

**확인 결과**

온도 데이터는 **14개 LOT 전체를 합친 345,390행·24열**입니다. 한 행은 특정 LOT의 한 시점에 기록된 센서·제어값 묶음이며, `LOT_NO`는 해당 행이 14개 LOT 중 어느 LOT에 속하는지 나타냅니다. LOT별 관측 지속 시간은 평균 약 423.6분, 최단 74.6분, 최장 812.6분입니다.

근거: [01_eda_3_lot_segments — LOT 구간](../notebooks/01_eda_3_lot_segments.ipynb).

**왜 확인하는가**

인접 행을 서로 독립적인 사례로 가정하면 데이터의 양을 과대평가할 수 있습니다. LOT를 기본 분석 그룹으로 사용하고, 운영 조건이 달라지는 내부 구간은 세그먼트 분리를 검토합니다.

**이어지는 질문과 검증 방법**

1. LOT는 실제로 어떤 생산 단위인가? → 데이터 사전과 제공자의 정의를 확인합니다.
2. 왜 LOT 길이가 다른가? → 생산량·강종과 자료 추출 범위를 대조합니다.
3. 긴 LOT가 결과를 지배하는가? → 전체·LOT별 통계를 함께 보고 향후 경보는 관측 시간당 발생률도 비교합니다.

산출물: LOT별 시작·끝·행 수·지속 시간 요약표.

## 2. 시간

**확인 결과**

온도 시각은 `MEAS_DT`, 이벤트 시각은 `EVT_DT`, 정비 기간은 `STRT_DT`~`END_DT`입니다.

**온도 관측 범위는 2024년 1월 2일~12월 28일**이며, 정확한 최초·최종 시각은 **2024-01-02 03:36:00 ~ 2024-12-28 16:44:24**입니다. 이는 14개 LOT 전체의 최초·최종 관측 시각으로, 이 기간 내내 연속해서 관측했다는 뜻은 아닙니다. LOT 사이에는 관측 공백이 있습니다. 타임존과 공식 수집 주기는 추가 확인이 필요합니다.

아래 표는 **14개 LOT 각각의 내부에서 계산한 측정 간격을 전체 합산한 분포**입니다. `LOT_NO`별로 시각을 정렬한 뒤 인접한 두 행의 시간 차이를 계산하며, 서로 다른 LOT 사이의 시간 차이는 포함하지 않습니다. 각 LOT의 첫 행은 비교할 직전 행이 없으므로 제외되어, 총 간격 수는 **345,390행 − 14개 LOT의 첫 행 = 345,376개**입니다. 비율의 분모도 이 전체 간격 수입니다.

| 간격 | 건수 | 비율 |
| ---: | ---: | ---: |
| 1초 | 334,966 | 96.9859% |
| 2초 | 10,372 | 3.0031% |
| 3초 | 31 | 0.0090% |
| 5초 | 1 | 0.0003% |
| 6초 | 2 | 0.0006% |
| 10초 | 1 | 0.0003% |
| 11초 | 3 | 0.0009% |

근거: [01_eda_1_sampling_interval — 측정 간격](../notebooks/01_eda_1_sampling_interval.ipynb), [01_eda_2_time_range_gaps — 기간·공백](../notebooks/01_eda_2_time_range_gaps.ipynb).

**왜 확인하는가**

모든 행이 정확히 1초 간격으로 기록된 것은 아니므로, 값이 얼마나 변했는지와 함께 실제로 몇 초가 지났는지를 확인해야 합니다. 예를 들어 온도값이 100에서 110으로 변했을 때, 1초가 걸렸다면 초당 변화량은 10이지만 10초가 걸렸다면 초당 변화량은 1입니다. 시간 차이를 무시하면 천천히 변한 구간을 급격히 변한 구간으로 잘못 판단할 수 있습니다. 마찬가지로 최근 60개 행의 평균이 항상 최근 60초의 평균인 것은 아닙니다.

같은 LOT 안에서 측정 간격이 11초로 벌어진 경우와, 한 LOT가 끝나고 다음 LOT가 두 달 뒤 시작한 경우도 구분해야 합니다. 전자는 해당 LOT의 수집 간격이 왜 길어졌는지 확인할 대상입니다. 후자는 두 LOT 사이에 관측 자료가 없다는 뜻이며, 그 기간 내내 설비가 고장 났거나 수집이 누락되었다고 단정할 수 없습니다. 따라서 서로 다른 LOT의 마지막 값과 첫 값을 연속 측정값처럼 이어서 변화율이나 이동평균을 계산하지 않습니다.

여기서 **1초는 데이터에서 가장 많이 나타난 간격**이고, **`10초 초과`는 노트북에서 긴 공백을 찾아보기 위해 정한 검색 조건**입니다. 공식 수집 사양을 확인하기 전에는 1초보다 길다고 누락으로 확정할 수 없으며, 10초를 넘었다고 설비 고장으로 판단할 수도 없습니다. 확인하려는 것은 **어느 LOT의 언제 간격이 벌어졌고, 그 전후 센서값·조업 이벤트·수집 상태에 어떤 변화가 있었는지**입니다.

**이어지는 질문과 검증 방법**

1. 왜 2초 이상 간격이 생기는가? → LOT×간격별 건수·비율·발생 시점을 확인합니다.
2. 간격이 벌어진 전후 센서값도 변하는가? → 직전·현재 시각, TC·OP, CR1 이벤트를 대조합니다.
3. 긴 공백은 정비 때문인가? → CR1 정비 기록과 비교합니다. 2024-01-02 15:04:30~2024-03-07 21:22:00 공백은 제공된 정비 날짜로 설명되지 않습니다.
4. 정비로 설명되지 않으면 무엇 때문인가? → 가동·수집 기록과 추출 범위를 확인합니다. 근거가 없으면 원인 미확인 공백으로 남깁니다.

산출물: LOT별 간격 분포, 공백과 운영 기록 대조표.

## 3. 그룹

**확인 결과**

온도 데이터의 구간 식별자는 `LOT_NO`, 이벤트·정비의 설비 식별자는 `PLANT_CD`입니다. LOT 번호가 곧 강종이나 코일 번호를 뜻하는지는 확인되지 않았습니다.

근거: [01_eda_3_lot_segments — LOT 구간](../notebooks/01_eda_3_lot_segments.ipynb), [01_eda_4_event_overlap — 이벤트·정비](../notebooks/01_eda_4_event_overlap.ipynb).

**왜 확인하는가**

다른 설비·강종·운영 상태의 차이를 이상으로 오해하지 않기 위해 그룹을 구분합니다. CR1 온도에는 CR1 기록을 연결하고, 세그먼트 경계는 조건 변경과 관측 연속성을 근거로 정합니다.

**이어지는 질문과 검증 방법**

1. 같은 LOT가 떨어져 다시 등장하는가? → 시간순 연속 구간 수와 LOT 종류 수를 비교합니다.
2. 같은 강종이 여러 LOT에 반복되는가? → LOT–강종 대응표와 반복 수를 확인합니다.
3. 강종이 같으면 정상 조건도 같은가? → 목표 온도·라인 속도·소재 규격의 확보 여부를 확인합니다.
4. 강종별 기준을 만들 수 있는가? → 반복 LOT와 관측량을 확인합니다. 강종당 LOT가 하나라면 강종 효과와 LOT 효과를 분리하기 어렵습니다.

산출물: LOT·강종·운영 상태 대응표, 세그먼트 정의.

CR1 정비는 2024-06-10 ~ 06-14, 2024-11-05 ~ 11-10입니다. 이벤트 120건은 관측 구간 포함 기준의 미매칭이며, 기록 오류를 뜻하지 않습니다.

운영 변화와 센서 변화를 연결하기 위해 조인합니다. 이벤트에는 LOT 키가 없으므로 CR1 조건 적용 후 이벤트 시각과 LOT 시작·끝을 비교합니다. 정비는 기간 겹침으로 대조합니다. 전체 날짜 범위 겹침만으로 센서 전후 비교가 가능하다고 판단하지 않습니다.

현재 집계는 양끝 포함 비교이며 정비 날짜는 자정으로 해석했습니다. 실제 시각·종료일 포함 규칙은 추가 확인 대상입니다. CR1 정비 종료일 당일에도 LOT가 없어 이 차이는 중첩 0건 결과에 영향을 주지 않습니다. 전체 정비 기간 끝은 `01_eda_4_event_overlap`의 `STRT_DT.max()`가 아니라 `END_DT.max()`로 확인해야 합니다.

**이어지는 질문과 검증 방법**

1. 왜 이벤트는 많지만 비교 가능한 관측은 적은가? → 이벤트별 전후 관측 가능 시간을 기록합니다.
2. 이벤트가 LOT 시작과 겹치는가? → 변경 전 데이터가 없으면 전후 비교 불가로 표시합니다.
3. 이벤트 시각은 시작·완료·입력 중 무엇인가? → 기록 의미와 상태 유효 기간 확인 후 강종을 연결합니다.
4. 정비 전에 증상이 있었는가? → 6월 9일·15일, 11월 4일·13일 LOT를 비교 후보로 삼되 강종·목표 조건·정비 목적을 먼저 확인합니다.
5. 관측 끝과 시작이 실제 정지·재가동 시각인가? → 운영 기록이 없으면 전조·복구 효과를 확정하지 않습니다. 정기수리를 고장 라벨로 사용하지 않습니다.

## 6. 분할

**현재 상태와 적용 기준**

분할은 아직 확정하지 않았습니다. 같은 LOT가 학습·검증에 섞이지 않도록 그룹을 분리하고 시간 순서를 유지합니다. 전체 공통·강종별·LOT 내 과거 기준은 같은 평가 구간에서 비교합니다.

**왜 확인하는가**

유사한 행이나 미래 정보가 학습·검증 양쪽에 들어가면 평가가 낙관적으로 보일 수 있습니다.

**이어지는 질문과 검증 방법**

1. 14개 LOT로 각 조건을 학습·평가할 수 있는가? → 분할별 강종·LOT 수·관측량을 확인합니다.
2. 검증에만 있는 강종은 어떻게 처리하는가? → 미관측 조건의 적용 기준 또는 제외 근거를 정합니다.
3. 특정 LOT 선택 때문에 결과가 달라지는가? → 시간 순서를 지키는 가능한 분할에서 일관성을 확인합니다.
4. 정상 기준에 평가 정보가 들어갔는가? → 임곗값·전처리 통계의 산출 범위를 확인합니다. LOT 전체로 같은 LOT를 평가하는 사후 탐색과 온라인 탐지를 구분합니다.

산출물: 분할 시각·LOT 목록·강종 구성·미관측 조건 처리 규칙.

## 7. 전처리

**현재 상태와 적용 기준**

보간 방법·허용 길이·안정화 기준은 미확정입니다. LOT 사이 공백은 보간하지 않습니다. 스케일링·결측 대체 통계는 학습 구간에서만 fit하고 온라인 처리는 현재·과거 정보만 사용합니다.

정비와 겹치는 관측은 정상 기준 학습에서 제외합니다. 현재 CR1 정비 기간에는 제외할 온도 행이 없습니다. 강종변경 직후는 전환 구간으로 따로 검토하고 무조건 정상·이상으로 지정하지 않습니다. 안정 구간도 정상 후보일 뿐입니다.

**왜 확인하는가**

전처리가 실제 이상을 지우거나 가짜 변화를 만들 수 있고, 미래 값으로 과거 결측을 채우면 온라인 평가에 정보 누수가 발생할 수 있습니다.

**이어지는 질문과 검증 방법**

1. 결측을 채우면 급변이 사라지는가? → 원본과 처리 후 시계열·특징을 비교합니다.
2. 어느 길이까지 보간하는가? → 연속 결측 길이·센서 변화 속도·수집 사양을 근거로 정합니다.
3. 강종변경 후 언제 안정화되는가? → TC·OP 수준·변동과 목표 조건을 함께 확인합니다.
4. 미래 정보가 포함되는가? → 보간 방향·이동 창·이벤트 상태·정비 결과의 사용 시점을 검사합니다.

산출물: 제외·보간·안정화 규칙, fit 구간, 처리 전후 비교 근거.

## 8. 특징

**현재 상태와 비교 목적**

TC는 온도 상태를, OP는 제어 활동 변화를 확인하기 위해 사용합니다. 어느 신호가 더 유용한지는 미검증이며 TC 단독·OP 단독·결합을 비교할 계획입니다.

| 특징 후보 | 확인할 변화 | 정의 시 기록할 내용 |
| --- | --- | --- |
| 수준 이탈 | 기준 구간과의 차이 | 단위·기준 구간·표준화 |
| 변화율 | 갑작스러운 변화 | 실제 경과 시간으로 나눈 차이, 단위/초 |
| 이동평균·변동성 | 지속적인 수준·불안정성 변화 | 시간 창·최소 관측량·과거 길이 |
| 값 고정 시간 | 부분 구간의 고정 | 동일값 허용 오차·지속 시간 |
| TC–OP 관계·시차 | 출력 이후 온도 반응 변화 | 같은 존의 대응·지연·학습 구간 |

**왜 확인하는가**

온도가 일정해도 제어출력이 달라질 수 있고 출력 변화에 대한 온도 반응은 지연될 수 있습니다. 원시 값의 크기만 비교하면 단위·변동 범위 차이를 이상으로 오해할 수 있습니다.

**이어지는 질문과 검증 방법**

1. 온도는 일정한데 출력만 달라지면 무엇인가? → 같은 조건의 다른 구간과 비교합니다. 출력 변화만으로 열화를 확정하지 않습니다.
2. 출력 이후 온도 반응이 다르면 이상인가? → 평소 지연·조건 변화·데이터 품질을 먼저 확인합니다.
3. 60개 행과 60초가 같은가? → 시간 기준 창을 사용하고 최소 관측량·과거 부족 시 처리를 정합니다.
4. 값을 직접 비교해도 되는가? → 물리 단위·센서 대응을 확인합니다. `CP-Z4`·`CP-Z4M`은 정의·생성 규칙 확인 후 활용합니다.

특징은 LOT·세그먼트 경계를 넘지 않습니다. 구체적인 창·지연은 후속 실험에서 정하고 [실험 기록](03-experiment-log.md)에 남깁니다.

산출물: 특징별 정의·단위·시간 창·필요한 과거 길이·경계 처리 명세.

## 9. 테스트

**현재까지 확인한 상태**

지금까지는 5개 EDA를 통해 데이터가 언제, 어떤 LOT에서 기록되었고 측정 간격·결측·중복이 어떠한지 살펴봤습니다. 조업 이벤트와 정비 기록을 온도 데이터와 시간으로 대조할 수 있는지도 확인했습니다. 주요 수치는 로컬 CSV에서 별도로 재계산했습니다.

| 분석한 내용 | 현재 확인한 결과 |
| --- | --- |
| 측정 간격 | 14개 LOT별 내부 간격을 합산한 345,376개 중 약 96.99%는 1초이고, 2~11초 간격도 있습니다. LOT 사이의 시간 차이는 제외합니다. |
| 관측 기간과 공백 | **2024년 1월 2일~12월 28일** 범위의 자료이지만 중간에 관측되지 않은 기간이 있습니다. 연중 연속 데이터는 아닙니다. |
| LOT 구성 | 14개 LOT가 있으며 관측 지속 시간은 약 74.6~812.6분으로 다릅니다. |
| 결측·상수·중복 | 16개 컬럼에 결측이 있고 `OP-Z3`가 254건으로 가장 많습니다. 전체 상수 컬럼·완전 중복 행·중복 시각은 없습니다. |
| 이벤트·정비와의 대조 | CR1 이벤트 134건 중 실제 LOT 관측 구간에 포함되는 것은 14건입니다. CR1 정비 2건의 기간에는 온도 관측값이 없습니다. |

이 결과로 **데이터의 기본 구조와 추가로 살펴볼 지점**은 파악했습니다. 그러나 불규칙 간격·공백·결측이 왜 발생했는지, 강종별 정상 온도와 출력은 무엇인지, TC와 OP 중 어느 쪽이 실제 이상 징후를 더 잘 드러내는지는 아직 확인하지 않았습니다. 모델 학습과 성능 평가도 아직 수행하지 않았습니다.

**앞으로 검증하려는 목적**

검증의 목적은 **조업조건이 바뀌어서 나타난 변화, 데이터 수집 문제로 생긴 변화, 설비 점검이 필요한 변화를 구분할 수 있도록 분석 기준을 마련하는 것**입니다. 현재 발견한 차이를 곧바로 고장으로 판단하지 않고, 아래 질문을 확인한 뒤 모델링에 사용할 구간과 처리 방법을 정합니다.

| 앞으로 확인할 질문 | 확인 방법과 이유 |
| --- | --- |
| 측정 간격이 길어진 이유는 무엇인가? | 어느 LOT의 언제 발생했는지 찾고, 그 전후 TC·OP와 조업 이벤트를 비교합니다. 수집 간격 때문에 변화가 급격해 보인 것은 아닌지 확인합니다. |
| 관측 공백은 정비·정지 때문인가, 자료가 일부만 제공된 것인가? | 정비 날짜, 실제 가동·수집 기록, 자료 추출 범위를 대조합니다. 관측값이 없다는 이유만으로 설비 정지나 고장으로 판단하지 않기 위해서입니다. |
| 결측률이 낮아도 중요한 구간이 비어 있지는 않은가? | 결측이 연속으로 발생하는지, 여러 센서가 동시에 비는지, 강종변경 주변에 몰리는지 확인합니다. 결측 처리로 중요한 변화가 사라지는 것을 막기 위해서입니다. |
| 서로 비교할 수 있는 조업조건인가? | LOT별 강종과 확보 가능한 목표 온도·운영 조건을 확인합니다. 정상적인 조건 차이를 이상으로 탐지하지 않도록 비교 기준을 정합니다. |
| 이벤트 전후나 정비 전후를 실제로 비교할 수 있는가? | 전후 센서값의 존재 여부와 관측 시간을 확인합니다. 비교할 데이터가 없는 구간에서 전조나 정비 효과를 추정하지 않기 위해서입니다. |
| 가공한 데이터에도 원래의 시간·LOT 관계가 유지되는가? | 이벤트를 연결한 뒤 행이 중복되지 않았는지, 결측 대체나 이동평균에 다른 LOT·미래 값이 섞이지 않았는지 검사합니다. 데이터 처리 자체가 잘못된 이상 신호를 만들지 않도록 하기 위해서입니다. |
| 학습과 평가를 공정하게 나눌 수 있는가? | 같은 LOT가 학습·평가에 함께 들어가지 않는지, 각 구간에 어떤 강종이 있는지 확인합니다. 이미 본 구간을 다시 맞힌 결과를 새로운 상황의 탐지 성능으로 오해하지 않기 위해서입니다. |

시간 순서도 아직 별도로 확인할 부분이 있습니다. `01_eda_1_sampling_interval`은 데이터를 시간순으로 정렬한 다음 간격을 계산합니다. 따라서 정렬 후 음수 간격이 없다는 사실은 원본 파일도 처음부터 시간순이었다는 뜻이 아닙니다. 원본에서 시간이 거꾸로 기록된 행이 있는지는 정렬하기 전에 검사해야 합니다.

이러한 검사는 일부 기초 집계와 별개로, 모두 자동 실행되도록 구현된 상태는 아닙니다. 앞으로 각 질문의 확인 결과와 미확정 사항을 남기고, 반복해서 확인할 조건은 코드로 검사할 수 있도록 정리합니다.

**후속 평가에서 확인할 질문**

경보가 많으면 더 좋은 탐지인가? 같은 평가 LOT와 임곗값 선정 절차에서 관측 시간당 경보 수·지속성·이벤트 및 결측 중첩·후보 근거를 비교해야 합니다. 실제 고장·품질 라벨 없이 정확도·미탐률·고장 조기 탐지 성능을 주장하지 않습니다.

**완료 기준**

- [ ] 주요 수치를 동일 데이터·계산 조건으로 재현한다.
- [ ] LOT·시간·강종·정비·품질의 연결 근거와 미확정 원인을 기록한다.
- [ ] 분할·전처리·특징 규칙과 예외 처리를 명시한다.
- [ ] 미래 정보 사용과 그룹 경계 침범 여부를 검증한다.
- [ ] 비교 조건과 후보별 검토 양식을 [실험 기록](03-experiment-log.md)에 연결한다.

검증 완료는 모든 원인을 확정하는 것이 아니라, 모델링에 사용할 범위와 추가 확인할 조건을 명시하는 것입니다.
