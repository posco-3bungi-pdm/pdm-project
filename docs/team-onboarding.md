# 첫 팀 협업 확인

이 문서는 팀이 실제 PR 리뷰를 시작하기 위한 첫 변경입니다.

## 팀원이 확인할 것

1. README와 CONTRIBUTING을 읽고 자신의 작업 환경을 준비합니다.
2. 저장소의 Issue 양식에서 목적과 완료 기준을 확인합니다.
3. 이 PR의 Files changed에서 변경 내용을 읽습니다.
4. Checks에서 Repository checks가 통과했는지 확인합니다.
5. 동의하면 Review changes → Approve를 선택합니다. 수정이 필요하면 근거와 함께 제안합니다.
6. 작성자 외 3명 이상의 승인이 모이면 Squash and merge로 합칩니다.

작성자 자신의 승인은 집계되지 않습니다. 새 커밋을 올리면 기존 승인은 무효화되므로 다시 검토합니다. 담당자는 팀의 실제 합의에 따라 바꿉니다.

## 다음에 정할 것

- 최종 주제와 대상 설비, 저장소 이름
- 역할별 책임 범위와 담당 파일
- 분석 단위, 데이터 출처와 이용 조건
- 게이트 일정과 마일스톤 기한
- 분석 코드가 추가될 때 실행할 테스트

## 현재 관리 방식

기존 조직 멤버에게 저장소 Write 이상 권한을 부여했습니다. 별도 GitHub Team과 조직 Projects 보드는 아직 생성하지 않았으며, 현재는 Issue·라벨·마일스톤으로 작업을 관리합니다.

CI는 파일 정책·Python 문법·노트북 스키마를 확인합니다. 분석 결과나 데이터 누수의 타당성은 사람이 검토하고 후속 분석 테스트로 보강합니다.
